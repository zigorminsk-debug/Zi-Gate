## Что делает приложение

1. **Отслеживает положение телефона по GPS** в фоне через постоянный
   foreground-сервис.
2. **Автоматически звонит на номер шлагбаума**, как только телефон попадает
   в его зону (радиус вокруг заданной точки). Звонок совершается напрямую
   через `ACTION_CALL` — **без дополнительных запросов и подтверждений**
   (пользователь один раз выдал разрешение `CALL_PHONE` при установке).
3. **Запускается вместе с телефоном** (приёмник `BOOT_COMPLETED`) и работает
   в фоне (`START_STICKY`, foreground-сервис, будильники/WakeLock).
4. **Получает все необходимые разрешения** при первом запуске (см. ниже) и
   просит исключение из оптимизации батареи.
5. **Адаптивная частота опроса GPS**: чем ближе к шлагбауму — тем чаще
   опрашиваем, чем дальше — тем реже. Это экономит батарею. В пределах
   **200 м от границы** частота фиксированная (1/2/3/10 с), дальше — плавная
   адаптивная кривая.
6. **Пауза опроса при подключении к выбранным Wi-Fi сетям** и
   автоматическое возобновление после отключения от них.
7. Выбор Wi-Fi сетей — **чекбоксы из сохранённых (configured) сетей** телефона.
8. **Синхронизация списка шлагбаумов** (отправка и получение): через буфер
   обмена (JSON) и/или через HTTP-сервер (POST/GET).

## Математическая модель адаптивного опроса GPS

Задача: **чем ближе к шлагбауму — тем чаще опрос; чем дальше — тем реже**,
чтобы экономить батарею. Мы опрашиваем позицию не с фиксированным периодом, а
по плавной функции от расстояния до ближайшей зоны.

### Обозначения

| Символ | Значение | По умолчанию |
|---|---|---|
| `T_min` | минимальный период — внутри/на границе зоны | **1.5 с** |
| `T_max` | максимальный период — далеко от всех зон | **60 с** |
| `d` | расстояние от телефона до центра ближайшего шлагбаума | — |
| `r` | радиус зоны ближайшего шлагбаума | задаётся |
| `L` | «длина релаксации» — сколько метров подхода нужно, чтобы период заметно изменился: `L = max(200, 1.5·r)` | — |
| `p` | показатель формы кривой (управляет «резкостью» перехода) | **1.3** |

### Часть 1 — период по расстоянию

Нормируем расстояние за границей зоны:

```
x = max(d - r, 0) / L          // x = 0 — прямо на границе
```

Вводим «близость» (closeness), равную 1 у границы и стремящуюся к 0 вдали:

```
c = exp(-x^p)                  // c ∈ (0, 1]
```

Базовый период по расстоянию:

```
T_base(d) = T_min + (T_max - T_min) · (1 - c)
```

### Часть 2 — скорость движения (приближение / удаление)

Помимо расстояния, модель учитывает **радиальную скорость** — как быстро
меняется расстояние до шлагбаума:

```
v = Δ(расстояние) / Δt   [м/с]
   v < 0  →  расстояние уменьшается  →  ПРИБЛИЖАЕМСЯ (едем к шлагбауму)
   v > 0  →  расстояние растёт       →  УДАЛЯЕМСЯ   (отъезжаем)
   v ≈ 0  →  стоим на месте
```

Период умножается на скоростной коэффициент:

```
F(v) = clamp(1 + v · k, 0.25, 4.0)   ,   k = 0.06 с/(м/с)
T(d, v) = T_base(d) · F(v)
```

Смысл:
* чем **быстрее приближаемся** (`v` всё более отрицательный) → `F < 1` → **интервал короче** → опрашиваем чаще, чтобы **не проспать момент входа в зону** при езде на большой скорости;
* чем **быстрее удаляемся** (`v` всё более положительный) → `F > 1` → **интервал длиннее** → батарея экономится, ведь шлагбаум и так удаляется;
* **стоим на месте** (`v ≈ 0`) → `F ≈ 1` → работает кривая по расстоянию.

### Часть 0 — фиксированные полосы опроса возле границы

По явной просьбе период опроса больше не только плавная кривая. Вблизи зоны он
принимает **точные фиксированные значения** (замер от границы зоны, т.е.
`beyond = (расстояние до центра) − (радиус)`; внутри зоны `beyond ≤ 0`):

| За границей зоны | Период опроса |
|---:|---:|
| 0 … 50 м | **1 с** |
| 0 … 100 м | **2 с** |
| 0 … 150 м | **3 с** |
| 0 … 200 м | **10 с** |
| дальше 200 м | адаптивная кривая ниже |

Эти значения **не зависят от скорости** и **не добавляют джиттер** — телефон
опрашивает GPS именно так, как задано. Это гарантирует, что на подъезде к
шлагбауму позиция обновляется часто, и звонок срабатывает точно на границе.

### Повторный звонок в зоне

Пока телефон остаётся **внутри** зоны, звонок повторяется через
**`repeatIntervalSec`** у каждого шлагбаума — задаётся в диалоге
добавления/редактирования в диапазоне **5–180 секунд** (по умолчанию **60 с =
1 минута**). Как только телефон **вышел из зоны**, таймер повторного звонка
сбрасывается, поэтому при следующем входе звонок прозвучит сразу.

Всё ограничено `T_min…T_max` и добаляется **джиттер ±5%** против одновременных
пробуждений. «Скорость» достигается пересчётом радиального сближения после
каждого фикса GPS (по последним двум точкам), поэтому даже при 90 км/ч точка
входа в зону не пропускается.

### Пределы (проверка)

* Внутри зоны и до +50 м за границей — **ровно 1 с** (первая полоса).
* На +100 м — **2 с**, на +150 м — **3 с**, на +200 м — **10 с** (полосы точные,
  независимо от скорости).
* Дальше 200 м работает адаптивная кривая: `d = r`  ⇒ `x = 0`  ⇒ `c = 1`  ⇒
  `T_base = T_min` — **часто**; `d ≫ r`  ⇒ `c → 0`  ⇒ `T_base → T_max` — **редко**.
* Приближение на 25 м/с → `F = 0.25` — период сокращается в 4 раза (только вне
  фиксированных полос).
* Удаление на 25 м/с → `F = 4` — период растёт до предела `T_max`.

Вне полос кривая непрерывна, гладкая и монотонная — нет «скачков» на границе
адаптивной зоны.

### Пример: радиус зоны `r = 40 м` (`L = 200 м`, `p = 1.3`)

| Расстояние `d`, м | За границей (`d−r`) | Источник | Период опроса |
|---:|---:|---|---:|
| 0–40 (в зоне) | ≤ 0 | полоса 1 | **1.00 с** |
| 90 | 50 | полоса 1 | **1.00 с** |
| 140 | 100 | полоса 2 | **2.00 с** |
| 190 | 150 | полоса 3 | **3.00 с** |
| 240 | 200 | полоса 4 | **10.00 с** |
| 300 | 260 | адаптивная | ~45.5 с |
| 500 | 460 | адаптивная | ~56.9 с |
| 1000 | 960 | адаптивная | ≈60.00 с |

**Физический смысл.** Подъезжая к шлагбауму, телефон опрашивает GPS по
фиксированным полосам: за 50 м — каждую секунду, и так часто, что звонок
срабатывает точно на границе. По мере удаления период плавно растёт и на
расстоянии порядка километра и более достигает 60 с — GPS почти не тратит
энергию, пока телефон не начнёт приближаться.

Реализация — `util/AdaptivePolling.kt` (функция `intervalMs(distance, radius)`).

## Пауза при подключении к Wi-Fi

Включён режим «Пауза при подключении к Wi-Fi» и выбраны сети (чекбоксы из
сохранённых сетей). Логика в сервисе:

* Подключились к выбранной сети → `pausedByWifi = true` → **GPS отключается**,
  опрос прекращается (экономия батареи и трафика).
* Отключились от сети / переключились на мобильные данные → `pausedByWifi = false`
  → **GPS и опрос возобновляются** на следующем цикле.

Сервис слушает изменения Wi-Fi/соединения (`broadcast` + `ConnectivityManager`)
и пересчитывает состояние даже при выключенном экране.

**Кнопка «Сохранить».** Диалог выбора Wi-Fi сетей — собственный диалог с
явной, всегда видимой кнопкой **«Сохранить»** внизу (как в диалоге шлагбаума),
поэтому выбор сетей не потерять. Нажатие «Сохранить» записывает отмеченные
сети (вместе с введёнными вручную) и сразу применяет их.

**Warm-up после отключения Wi-Fi.** Как только подключение к выбранной сети
разрывается, приложение не просто «включает GPS снова», а делает **короткий
залп из 6 быстрых фиксов GPS** (по 1 с). Позиция при этом **не прыгает по
промежуточным точкам**: в конце залпа выбирается **один лучший фикс** (с
наименьшей погрешностью) и только он становится новой позицией. Во время залпа
статус показывает **«уточнение GPS…»**, звонки не совершаются. Это нужно, чтобы
адаптивная модель опроса стартовала с актуального расстояния, а не с устаревшей
оценки «до паузы» — и чтобы грубый первый фикс (ложные «7 м») не мелькал на
экране и не вызывал ложный звонок. После залпа модель переходит к обычному
адаптивному периоду.

### Интервалы опроса издалека (v1.19)

Дальше 400 м от всех шлагбаумов сервис работает на сетевой геолокации (GPS выключен, батарея экономится). Потолок интервала теперь ступенчатый: дальше 1 км — до 60 с (там ничего не происходит, спешить некуда), ближе 1 км — до 30 с (заметнее приближение), ближе 300 м — точный GPS с полосами 1/2/3/10 с. Также: подпись «Последняя точка» больше не переносится по буквам, имя шлагбаума показывается без лишних пробелов.

## Звонок с карточки (v1.19)

Тап по иконке шлагбаума на карточке — немедленный звонок на его номер (как автозвонок: без лишних подтверждений). Если прямой вызов заблокирован системой — откроется набор номера с уже введённым номером. Редактирование карточки по-прежнему открывается тапом по самой карточке или кнопкой «Редактировать».

## Энергопотребление (v1.19)

Сервис тратит батарею настолько, насколько это действительно нужно точности:

- **Дальше 400 м от всех шлагбаумов** — используется сетевая геолокация (NETWORK_PROVIDER): она почти не тратит батарею по сравнению с GPS-приёмником, который иначе ищет сигнал круглые сутки (особенно в помещении). Точность тут не критична — нужно лишь видеть «далеко/близко».
- **Ближе 300 м** — включается полноценный GPS: метровая точность там, где принимается решение о звонке. Полосы 1/2/3/10 с и все фильтры работают как раньше.
- **300–400 м** — гистерезис, чтобы режимы не переключались туда-сюда.
- **В сетевом режиме период не длиннее 30 с** (вместо 60 с): сетевые фиксы почти бесплатны, зато расстояние обновляется вдвое чаще.
- Скорость сближения считается только по точным фиксам (±50 м), чтобы грубая сетевая точка не «дёргала» модель опроса.
- Пауза на выбранном Wi-Fi полностью останавливает опрос (0% GPS).
- Интерфейс не перечитывает список шлагбаумов на каждом обновлении статуса (раньше — раз в секунду).

Точность определения координат не пострадала: вся триггерная зона и зоны быстрого опроса (200 м от границы) всегда обслуживаются GPS.

## Стабильность дистанции (v1.19)

* **Отсев плохих фиксов**: отбрасываются точки с точностью хуже ±80 м, старше
  2 минут, нулевые и mock-точки.
* **Фильтр стоянки**: если сдвиг меньше погрешности GPS и скорость около нуля,
  позиция **заморожена** — дистанция не прыгает 29→70 м, пока телефон лежит
  неподвижно.
* **Звонок только по подтверждённой точке**: нужны **2 подряд фикса внутри
  зоны** при хорошей точности (или 1 глубокий: `дистанция + точность` внутри
  зоны). Одиночный грубый фикс звонок не вызывает.
* **Сглаженная скорость**: радиальная скорость для адаптивного опроса
  усредняется, одиночный скачок не дёргает период опроса.
* Статус «Последняя точка» показывает **время именно фикса** (а не текущее),
  **имя ближайшего шлагбаума** и **точность** (например,
  «12:03:44 · Стройка: 112 м (±14 м)»).

## Разрешения

| Разрешение | Зачем |
|---|---|
| `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION` | GPS: определение входа в зону шлагбаума |
| `CALL_PHONE` | Автоматический звонок на номер шлагбаума (`ACTION_CALL` без запросов) |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION` | Постоянная работа в фоне (тип `location`) |
| `RECEIVE_BOOT_COMPLETED` | Запуск вместе с телефоном |
| `POST_NOTIFICATIONS` | Уведомление о работающем сервисе (Android 13+) |
| `ACCESS_WIFI_STATE`, `ACCESS_NETWORK_STATE`, `CHANGE_WIFI_STATE` | Определение подключения к выбранным Wi-Fi сетям |
| `INTERNET` | Отправка/получение списка шлагбаумов (синхронизация) |
| `WAKE_LOCK` | Служба не «засыпает» с выключенным экраном |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | Исключение из ограничений батареи для надёжной работы GPS |

При первом запуске приложение запрашивает геолокацию, звонки и уведомления и
показывает диалог исключения из оптимизации батареи.

## Синхронизация шлагбаумов (отправка / получение)

Кнопка **«Загрузить / Отправить»** открывает диалог:

* **📤 Отправить на сервер (POST)** — JSON-массив шлагбаумов уходит на заданный
  URL (если поле пустое — копируется в буфер).
* **📥 Загрузить с сервера (GET)** — скачивается JSON и импортируется в список
  (новые записи добавляются, дубликаты пропускаются по `id`).
* **📋 Копировать барьеры (JSON)** — выгрузка в буфер обмена.
* **📄 Вставить из буфера** — импорт из буфера обмена.

Формат обмена — JSON-массив:

```json
[
  {
    "id": "…uuid…",
    "name": "Шлагбаум",
    "phone": "+375293371412",
    "lat": 53.9,
    "lng": 27.56,
    "radius": 40.0,
    "enabled": true,
    "lastTriggeredAt": 0
  }
]
```

Так синхронизируются **добавленные шлагбаумы** между устройствами.

## Выбор Wi-Fi сетей (пауза опроса)

Кнопка «Выбрать Wi-Fi сети» открывает диалог с чекбоксами. В список
попадают:

* **сохранённые сети** телефона (`WifiManager.getConfiguredNetworks()`) —
  доступны на старых Android;
* **видимые рядом сети** (результаты сканирования `getScanResults()`);
* сети, добавленные **вручную** через поле «Название сети (SSID)» + «Добавить».

> ⚠️ **Важно:** начиная с Android 10/12 обычные (не системные) приложения
> **не могут прочитать список сохранённых сетей** — это ограничено
> системным разрешением `NETWORK_SETTINGS`. Поэтому список настроен так,
> чтобы показывать сети из сканирования и позволять ввести нужную вручную.
> Так выбор работает на любой версии Android.

Чтобы сканирование показывало сети, включите **геолокацию** (GPS) и дайте
приложению разрешение на местоположение. Если список пуст — введите название
сети вручную.

## Управление шлагбаумами

* **Добавить** — кнопка «Добавить шлагбаум», заполнить название, номер, радиус
  и нажать «Запросить координаты» (или ввести координаты).
* **Редактировать** — нажмите на карточку шлагбаума или на кнопку
  ✏️ **Редактировать** рядом с ним. Откроется тот же диалог с уже
  заполненными данными; после изменения нажмите «Сохранить изменения».
* **Удалить** — кнопка 🗑 рядом с шлагбаумом.
* **📍 Записать координаты** — кнопка внизу карточки: стоя **возле
  шлагбаума**, нажмите её, чтобы приложение сняло текущую GPS-позицию и
  записало её как центр зоны этого шлагбаума (без ручного ввода координат).
* **Иконка шлагбаума** — при добавлении/редактировании в диалоге можно
  выбрать одну из **5 иконок** (кнопки-фишки). Выбранная иконка отображается
  слева в карточке шлагбаума.

* **📏 Цифра расстояния на карточке** — это расстояние от **текущей GPS-позиции
  телефона** до **этого конкретного шлагбаума**. Поле «Последняя точка» в
  статусе — расстояние до **ближайшего** шлагбаума, и теперь оно подписано
  **именем** этого шлагбаума (например, «Стройка: 53 м»), чтобы цифра не
  выглядела загадочной. Карточки и статус считаются от **одного и того же**
  последнего фикса GPS (раньше карточки брали другой кэшированный источник и
  могли расходиться).

При сохранении изменений сохраняются и идентификатор (чтобы не потерять статус
синхронизации), и время последнего звонка (чтобы не сработал повторный вызов).

### Иконка приложения (v1.19)
* **Иконка лаунчера** — монограмма **«Z»** от **Z I Gate**, нижний правый хвост
  которой переходит в **оранжевый шлагбаум** (поднятая стрела). Адаптивная
  векторная иконка на синем фоне `#0B5FA5`.

### Диалог добавления/редактирования (v1.19)
* Поля **подписаны** (Название / Номер / Радиус / Повтор), значения — тёмным
  контрастным текстом, чтобы не было «белого на белом».
* Кнопка **«Сохранить»** всегда видна внизу диалога (свои явные кнопки, а не
  скрытые кнопки системного `AlertDialog`).
* Диалог прокручивается, поэтому ничего не обрезается даже при открытой
  клавиатуре.
* Кнопка **«Запросить координаты»** **сразу включает GPS и ждёт свежий фикс**
  (не использует старую кэшированную точку) — во время запроса подпись меняется
  на «Запрос координат…», а при получении точки она подставляется как центр
  зоны. Кнопка «📍 Записать координаты» на карточке работает так же.

## ⚠️ Почему автозвонок может «не идти» — важно прочитать

На современных Android (10+) есть системное ограничение: **приложение,
работающее в фоне (даже foreground-сервис), не может само запускать
активности** — то есть `ACTION_CALL` (который открывает телефонное приложение
и набирает номер) **блокируется из фона**. Именно из-за этого вы можете
находиться в зоне шлагбаума (0 м), но звонок «не пойдёт».

**Решение.** Приложению нужно разрешение **«Поверх других приложений»
(`Display over other apps` / `SYSTEM_ALERT_WINDOW`)** — оно официально даёт
право запускать активности из фона. ZI Gate **запрашивает его при первом
запуске** (открывается экран настроек) и показывает предупреждение ⚠ в
настройках, если оно выключено.

**Как включить вручную (если предупреждение видно):**
Настройки → Приложения → **ZI Gate** → **Поверх других приложений** → Вкл.
(На некоторых прошивках путь: Настройки → Приложения → ZI Gate → Дополнительно
→ «Поверх других приложений» → разрешить.)

Дополнительно:
* Разрешение **звонки** (`CALL_PHONE`) — выдаётся при первом запуске.
* Разрешение **геолокация** — для работы GPS.
* **Исключение из оптимизации батареи** — чтобы GPS не «засыпал».

### Диагностика
Раз в зоне приложение пишет в лог (`adb logcat -s ZIGATE`):
* `In zone: ... -> dial <номер>` — вход в зону и попытка набора;
* `placeCall: SecurityException ... (enable 'Display over other apps')` —
  звонок заблокирован системой из-за отсутствия разрешения наложения;
* `placeCall: CALL_PHONE permission not granted` — нет разрешения на звонки.

## Диагностика падений

Приложение **не может «молча» упасть при открытии**:

1. **Экран запуска защищён**: каждый шаг `onCreate` обёрнут в `runCatching`,
   поэтому одна сбойная операция показывает интерфейс по умолчанию, а не
   крашит приложение.
2. **При любой непойманной ошибке** открывается экран **«ZI Gate: ошибка»**
   с полным стек-трейсом, моделью устройства и версией Android, кнопками
   «📋 Скопировать» и «Закрыть». Скопируйте текст и пришлите мне.
3. Тот же отчёт дополнительно пишется в `Logcat` (тег `ZIGATE`) и в файл
   `zigate_crash.txt` в папке `Android/data/by.zakharevich.zigate/files/`.

Если вы видите экран ошибки — это уже не «приложение просто закрывается»,
а конкретное сообщение, по которому легко найти строку. Скопируйте его и
пришлите.

> Убедитесь, что установлена именно **v1.19**: Настройки → Приложения →
> ZI Gate → «Версия 1.11». Если вы уже ставили более старую версию, лучше
> **удалить её и поставить v1.19**, чтобы не осталось старых настроек.

## Важные ограничения и советы

* **Zвонок из фона.** `ACTION_CALL` запускает интерфейс телефона. На большинстве
  устройств работает, но некоторые OEM (Xiaomi, Huawei, Samsung и др.) могут
  ограничивать запуск активности из фона. Для надёжности держите сервис в
  foreground (он и есть foreground) и добавьте приложение в «Автозапуск» /
  исключение батареи в фирменных прошивках.
* **Foreground-сервис `location`** на Android 14 может быть ограничен при
  старте строго из фона. Поэтому после перезагрузки/установки лучше один раз
  открыть приложение и включить автоматику, тогда сервис поднимется корректно.
* **Точность GPS** зависит от погоды, плотной застройки и позиции телефона.
  Для калибровки используйте кнопку «Текущая позиция» при добавлении шлагбаума.
* **Адаптивный период** — это верхняя «лентяйская» граница. Если телефон
  движется, GPS всё равно присылает фиксы чаще (движение само по себе
  «будит» GPS), поэтому звонок в зоне происходит быстро.
* **Сохранённые Wi-Fi сети.** Список берётся из configured-сетей устройства.
  На некоторых версиях Android для его чтения/сканирования может требоваться
  разрешение на геолокацию (оно уже запрашивается).
* **Батарея.** Дополнительно рекомендуется предоставить исключение из
  оптимизации батареи (приложение само это предлагает).
