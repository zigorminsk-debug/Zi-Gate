## 2. Оптимизация энергопотребления (без потери точности)

Главный источник расхода был: **GPS-приёмник работает всегда**, даже когда до ближайшего шлагбаума километры (например, весь день в офисе/дома). В помещении GPS может вообще не ловить, но продолжать искать — это самый дорогой режим.

### Решение — двухрежимная геолокация с гистерезисом

| Расстояние до ближайшего шлагбаума | Режим | Почему точность не страдает |
|---|---|---|
| **< 300 м** | GPS | Вся триггерная зона и полосы 1/2/3/10 с (0–200 м от границы) обслуживаются точным GPS с запасом ≥100 м |
| **300–400 м** | сохраняется текущий режим | Гистерезис — нет «дребезга» переключений |
| **> 400 м** | сетевая геолокация | Для решения «далеко/близко» хватает точности ±20–80 м; на экране честно показывается `±N м` |
| фиксов ещё нет | сетевая (если доступна) | Холодный старт почти бесплатен, режим уточняется по факту |

Дополнительно:
- **В сетевом режиме период опроса ограничен 30 с** (вместо 60 с GPS): сетевые фиксы почти бесплатны, зато картина расстояния обновляется вдвое чаще, чем раньше, — реакция на выезд к шлагбауму улучшилась.
- **Скорость сближения считается только по фиксам точнее ±50 м** — грубая сетевая точка не может раскачать модель опроса ложным «движением».
- **Допуск грубости фикса зависит от режима**: GPS — до ±80 м, сеть — до ±200 м (иначе сетевые фиксы отбрасывались бы все).
- Пауза на выбранном Wi-Fi, как и раньше, останавливает опрос полностью.
- Интерфейс больше не делает файловый ввод-вывод каждую секунду (п. 2 таблицы).

Оценка эффекта: в типичном сценарии («весь день не у шлагбаума») GPS-приёмник теперь включается только при подъезде к шлагбауму. Расход сервиса вне зон приближения снижен до уровня сетевой геолокации (единицы % от прежнего), при этом всё, что происходит в 200 м от границы зоны, обслуживается GPS без изменений.

## 3. Что НЕ тронуто (осознанно)

- Полосы опроса 50→1 с / 100→2 с / 150→3 с / 200→10 с — по спецификации.
- `minifyEnabled false` — включение R8 сократит APK, но потребует прогонки правил; риск без эмулятора неоправдан.
- `WAKE_LOCK` в манифесте не используется напрямую (LocationManager держит CPU сам) — оставлен как страховка на некоторых прошивках.
- Geofencing API (Google Play services) не добавлен — зависит от наличия GMS на телефоне.
